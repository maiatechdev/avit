# Story 2.4 — Painel do professor com dados reais

Status: **Ready** (@sm cria, @po valida)

Referências: `docs/prd/prd-mvp-avit.md` (FR10, FR11), Story 2.2 (sessão), Story 2.3 (check-in), `app/PRODUCT.md` (princípio 4: dados honestos).

## Story

Como **professor**, quero ver o que aconteceu na minha sessão, com números reais e agregados, para planejar a próxima aula.

## Definições dos indicadores

Cada número tem uma regra. Nenhum mostra dado individual.

- **Alunos:** número de alunos que fizeram o check-in na sessão.
- **Engajamento:** % dos alunos que escolheram uma trilha.
- **Autonomia:** % das quatro trilhas que a turma usou (trilhas distintas escolhidas / 4).
- **Competência:** exercícios resolvidos na sessão, comparado ao número de alunos (limitado a 100%).
- **Vínculo:** % dos alunos que escolheram "Colaborar".
- **Distribuição por trilha:** quantos alunos escolheram cada trilha.
- **Onde a turma travou:** % dos alunos que marcaram "não entendi ainda" no check-in.
- **Sugestão:** texto fixo escolhido pela regra abaixo (a sugestão com IA entra na integração final com o Gemini).
  - Se "não entendi" ≥ 40%: "Retome o conceito de função antes de avançar com exercícios."
  - Se engajamento < 60%: "Confira se todos conseguiram entrar e escolher uma trilha."
  - Caso contrário: "A turma avançou bem. Proponha um desafio com a trilha Criar."

## Escopo

- **Dentro:** tabela `participations`; endpoint `POST /api/participations` para registrar a trilha; endpoint `GET /api/dashboard?sessionId=`; painel lendo dados reais; estado vazio quando não há respostas; testes das regras.
- **Fora:** sugestão gerada por IA (Gemini no final), exportação, gráficos por horário, login do professor.

## Critérios de aceite

1. Ao escolher uma trilha, o app registra a escolha no servidor com `sessionId`, `participantId` e `path`. Falha de rede não bloqueia o aluno.
2. `GET /api/dashboard?sessionId=` devolve os indicadores acima calculados a partir do banco, sem dados individuais.
3. O painel mostra esses valores no lugar dos números fixos. Quando a sessão não tem respostas, mostra "Ainda não há respostas nesta sessão".
4. A sugestão segue a regra descrita, e não há texto de demonstração escondido no código.
5. Sessão inexistente retorna 404 `session_not_found`.
6. `lint`, `typecheck`, `test` e `build` passam a partir de `socrates-ai/`.

## Dev Notes

- As tentativas do chat não são ligadas ao aluno, porque a rota de turno não recebe o `participantId`. Por isso "Competência" é medida pela sessão inteira, e não por aluno.
- Com poucas respostas, os percentuais parecem extremos. O painel mostra o número de alunos ao lado de cada percentual.
