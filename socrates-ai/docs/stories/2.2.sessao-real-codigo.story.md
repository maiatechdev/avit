# Story 2.2 — Sessão real com código de entrada

Status: **Done** (validada pelo usuário em produção)
Epic: 2 — Sessão real e caminhos
Referências: `docs/prd/prd-mvp-avit.md` (FR1, FR2), `docs/architecture/arquitetura-mvp.md` (seções 2 e 4), Story 1.1 (banco Neon e padrão de schema automático).

## Story

Como **professor**, quero ativar uma sessão e receber um código, para que a turma entre nela pelo próprio celular.

Como **aluno**, quero digitar o código da sessão, para que eu caia no objetivo certo da aula.

## Escopo

- **Dentro:** criação de sessão com objetivo (`POST /api/sessions`); entrada por código (`POST /api/sessions/join`); tabela `sessions` criada automaticamente; a tela do professor mostra o código e o objetivo reais; nova tela "Entrar com código" para o aluno; o chat usa o id da sessão real; o objetivo mostrado aos alunos vem da sessão.
- **Fora:** check-in do aluno (Story 2.3), painel com dados reais (Story 2.4), login de qualquer tipo, QR code funcional (fica para depois; hoje a tela mostra só o código).

## Critérios de aceite

1. `POST /api/sessions` com `{ objective }` (3 a 140 caracteres) cria uma sessão e devolve `{ id, code, objective }`. O código tem o formato `SOC-` seguido de 4 dígitos e é único.
2. `POST /api/sessions/join` com `{ code }` devolve `{ id, objective }` quando o código existe (sem diferenciar maiúsculas e espaços), e HTTP 404 `session_not_found` quando não existe.
3. A tela "Ativar sessão" cria a sessão ao ser confirmada e só avança quando a API responde. Se falhar, mostra erro e permite tentar de novo.
4. A tela "Sessão ativada" mostra o código e o objetivo da sessão criada, sem valores fixos.
5. A tela inicial tem a opção "Sou aluno" que leva a "Entrar com código". Um código válido leva à tela de caminhos com o objetivo da sessão; um código inválido mostra mensagem clara.
6. O chat envia o `sessionId` real da sessão, e não um valor gerado no navegador.
7. `lint`, `typecheck`, `test` e `build` passam a partir de `socrates-ai/`.

## Tarefas

- [ ] Função `POST /api/sessions` e `POST /api/sessions/join`.
- [ ] App: criação na ativação, tela de código, tela de entrada do aluno, objetivo e id reais no fluxo.

## Dev Notes

- Código no formato `SOC-1234`. Colisões são raras; se houver, a criação tenta de novo até 5 vezes.
- O id da sessão é gerado no servidor (UUID), o código é só a forma de entrada.
- Sem autenticação: quem tem o código entra. Isso é aceitável para a demo com dados fictícios.
